# SilentReg

A small Windows program that converts a `.reg` file into a standalone silent importer `.exe`. No installation or Python is needed. Requires Windows with .NET Framework 4.x (included in Windows 10/11).

## Use

1. Open **SilentReg.exe**.
2. Browse to a `.reg` file, or drag it onto the window.
3. Review **Request administrator access**. The converter suggests this for files containing hives other than HKEY_CURRENT_USER, but actual permissions depend on the keys.
4. Leave **Registry view** on Native unless your file needs the 32-bit or 64-bit view specifically.
5. Click **Create silent .exe**. The save dialog defaults to the input .reg file's folder; you can choose another destination.
6. Run the generated `.silent.exe` when you want to apply the changes.

Conversion does not import anything. The generated EXE contains the original file bytes; it works without the original `.reg` file or the converter. Your original file is unchanged. Only package registry files you have reviewed: every run of the generated EXE immediately applies its contents, including deletions.

## Creation confirmation setting

The **Silent importer ready** confirmation includes a checkbox labeled **dismiss prompt after 5 seconds**. Checking it saves the setting and starts a five-second countdown for the current confirmation. Future creation confirmations open with the checkbox checked and close automatically after five seconds. Unchecking it stops the countdown and saves automatic dismissal as off. **OK** always closes the confirmation immediately.

The setting starts off and is saved for the current Windows user in `%LOCALAPPDATA%\SilentReg\preferences.ini`, so it survives reopening the converter. If the preference cannot be saved, the dialog explains that it applies only to the current session. This setting affects only the converter's successful-creation confirmation. Creation errors still require acknowledgement, and generated importers continue to create no dialogs or log files.

## The three prompts

| Prompt | Generated importer behavior |
| --- | --- |
| UAC / allow changes to your device | Required when requesting administrator access from a non-elevated session. No additional UAC request when run from an already elevated process. |
| Registry Editor: do you want to continue? | Removed. The importer uses `reg.exe import`. |
| Registry Editor: successfully added | Removed. No log file is created. |

For writable current-user keys, leave administrator access unchecked to run without an elevation request. For protected machine keys, check it and approve UAC, or run from an already authorized administrator session. Converting a file cannot grant permissions or eliminate Windows' requirement for administrator approval. This tool does not change UAC settings or create scheduled tasks. Windows security software or organizational policies can show additional messages or block unsigned programs.

If elevation uses a different administrator account, HKEY_CURRENT_USER refers to that account. For files mixing user and machine settings, consider separate imports under the intended user and administrator contexts.

## Results and errors

The converter compiles in the local temporary folder and copies the finished importer to your selected folder, including synced drives. Temporary destination locks are retried for up to about four seconds. If the file stays locked, creation fails with the output path and a suggestion to close the program using it or choose another filename. A destination that remains locked is not truncated.

The importer shows no success or error dialog, opens no console window, and creates no log files, including on failure. Exit code 0 means `reg.exe` reported success; nonzero means failure. UAC cancellation occurs before the program starts. Importers generated by earlier versions must be recreated with this converter to remove their logging; existing log files are not deleted automatically.

Registry imports are not transactional: a failure can leave earlier entries applied. The converter checks the file extension and header, not every registry entry. It preserves the file's encoding and does not rewrite registry values. ANSI `REGEDIT4` files remain dependent on the target computer's code page. Use Registry Editor to export affected keys before applying changes if you need a backup; this program does not create backups automatically.

Native selects the operating system's default registry view (64-bit on 64-bit Windows). Selecting 64 on a 32-bit system can fail. The target computer must have .NET Framework 4.x and the Windows `reg.exe` utility available.

## Command line

The converter also accepts these options without opening a window. The example explicitly requests an optional build-status text file; generated importers never write logs:

```powershell
$process = Start-Process .\SilentReg.exe -ArgumentList '--input "C:\Files\settings.reg" --output "C:\Files\settings.silent.exe" --status "C:\Files\build-result.txt"' -Wait -PassThru
$process.ExitCode
```

Add `--admin` to request elevation when the generated importer runs. CLI mode defaults to no elevation. Use `--view Native`, `--view 32`, or `--view 64`, and `--force` to replace an existing output. `--status` is optional and records build success or an error. The converter returns 0 for successful creation and 1 for failure.

## Rebuild

Source is included. From this folder:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

The execution-policy option applies only to this build process. It does not change the machine's policy. The build uses the .NET Framework C# compiler already on Windows. `Runner.cs` is embedded source used to compile generated importers; `SilentReg.cs` contains the converter interface and builder.

## Tests

Run `powershell -NoProfile -ExecutionPolicy Bypass -File .\test.ps1` for 12 conversion checks. Add `-ApplyRegistry` for the full 27-check integration suite, including confirmation that successful and failed imports create no adjacent or fallback logs. Integration checks create a disposable GUID-named current-user test key and remove it in a finally block. Administrator importers are compiled and their manifests checked without launching a UAC request. The suite retains generated artifacts in a new `test-output-*` folder for inspection. An import exit code of 0 is Windows' reported result, not independent verification of every requested setting.

Microsoft references: [reg import](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/reg-import), [application execution levels](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests).

File-save regression checks: `powershell -NoProfile -ExecutionPolicy Bypass -File .\test-file-locks.ps1`. These check new and replacement outputs, transient and persistent locks, preservation of an existing locked file, and useful error messages without applying registry changes. All 11 checks passed on the J: working drive after the original rename failure was reproduced there.

Creation-confirmation tests: `powershell -NoProfile -ExecutionPolicy Bypass -File .\test-confirmation.ps1`. All 18 checks passed, including five-second timing, checkbox changes, manual dismissal, saved preferences, and save failures. The tests use invisible test windows and isolated temporary preferences; they do not modify the user's actual settings or registry.
